# cai2012: Cai & Wang's collisionless circular plume

!!! abstract "At a glance"

    | | |
    |---|---|
    | **Purpose** | Argon from a circular nozzle exit straight into vacuum, at Kn = 100, 0.1, 0.01, compared with Cai's collisionless analytical solution |
    | **Reference** | Cai, C., and Wang, L., *Numerical Validations for a Set of Collisionless Rocket Plume Solutions*, J. Spacecraft and Rockets 49(1), 2012 |
    | **Model** | 3-D Cartesian `dsmcFoam` (VHS, NTC); the nozzle exit *is* the DSMC inlet, through `plumeFieldInflow` |
    | **Evidence** | Unit-tested derivation, analytical solution and post-processing; **solver-tested** in `tests/openfoam` with short runs. Not a reproduction of Cai's DSMC numbers; no result is validated |
    | **Runs on** | Python for generation and `--dict-only`; OpenFOAM v2512 plus the `plumeFieldInflow` library for meshing and solving |
    | **Start in** | `cases/cai2012/` (study scripts) or `cases/cai2012/Cases/<case>/` (per-case scripts) |

## What this family is for

A uniform drifting Maxwellian on the disk r ≤ D/2 at x = 0 (D = 0.2 m, speed
ratio S₀ = 2) expands into vacuum. Cai derived the collisionless solution for
this problem in closed form; at Kn = 100 a DSMC solution should approach it, and
at Kn = 0.1 and 0.01 collisions should pull it away in a known direction. What
the family checks is that *trend*, on 3-D OpenFOAM — not agreement with Cai's
axisymmetric GRASP numbers, which used a different solver and a much finer grid.
[The Cai 2012 family](../cai2012-case.md) records every paper value,
assumption and difference.

Each Knudsen case is generated at four numerical-particle levels (1×, 2×, 5×,
10× the baseline parcel population), so the committed study is 3 × 4 = 12
cases. A level changes `nEquivalentParticles` and nothing else.

## Geometry and coordinates

| | |
|---|---|
| Exit | disk of radius R₀ = D/2 at x = 0, centred on the axis |
| Plume axis | +x (`geometry.plume_axis: [1, 0, 0]`) |
| Domain | 0 ≤ X/D ≤ 10, \|Y\|/D ≤ 10, \|Z\|/D ≤ 10 (`geometry.*_over_D`) |
| Symmetry | none: full 3-D (`geometry.symmetry_mode: none`; `half_y` is opt-in) |
| Patches | `nozzle` (injects), `upstreamVacuum` (rest of x = 0, deletes), `vacuum` (five other faces, deletes) |
| Mesh | graded multi-block Cartesian box, uniform core around the exit; the nozzle is carved from x = 0 by `topoSet` + `createPatch`, so it is a staircase whose area is checked against πR₀² |

Normalised outputs use Cai's variables: X/D, n/n₀, U₁√β₀ and T/T₀, with
β₀ = 1/(2RT₀) and S₀ = U₀√β₀. The equations are in
[`plumetools.cai2012.analytical`](../reference/api/cai2012/analytical.md).

## Prerequisites

| Step | Needs |
|---|---|
| `generate_cases.py`, `validate_cases.py`, `Allmesh --dict-only` | Python ≥ 3.9 with `plumetools` (numpy, scipy, PyYAML). **No CaseFoam**: the study is a flat list, cloned with `shutil.copytree` |
| `Allmesh` | `blockMesh`, `topoSet`, `createPatch`, `checkMesh` |
| `Allrun` | `dsmcInitialise`, `dsmcFoam`, and **`libplumeDsmcBoundaryModels.so`** (built by `./Allsetup` or `applications/dsmcBoundaryModels/Allwmake`); `decomposePar`, `mpirun`, `reconstructPar` for parallel; `foamDictionary` for `-np` |
| `Allpost` | `postProcess` (cell centres and volumes); matplotlib for the figures |
| imagery in `AllpostCases` | ParaView's `pvpython` (optional; skipped with a message if absent) |

The case **fails** if the inflow library is not built; there is deliberately
no fallback to stock `FreeStream`, which would inject on every vacuum boundary
([why](../plume-field-inflow.md)).

## Inputs

Two files, with different roles. Both loaders reject unknown keys.

| File | Role | Loader |
|---|---|---|
| `study.yaml` | the matrix: which Knudsen cases and particle levels exist, per-case `overrides`, study-wide run-length and write-rate multipliers | `plumetools.cai2012.study.load_study` |
| `baseCase/case.yaml` | **the authoritative physics**: nozzle, exit state, gas, domain, mesh, DSMC, checks, post-processing. Cloned into every case, with `exit.knudsen` and `dsmc.numerical_particle_multiplier` rewritten per case | `plumetools.cai2012.config.load_case_config` |

Only the Knudsen number is a per-case physical input; the rest is derived when
a case is meshed:

| Derived | From | Where |
|---|---|---|
| λ₀ = Kn·D | `exit.knudsen`, `nozzle.diameter_m`, `exit.characteristic_length` (`diameter`) | `cai2012.gas` |
| n₀ | λ₀, T₀ and the VHS gas (`gas.mean_free_path_convention: vhs`) | `cai2012.gas` |
| U₀ = S₀√(2RT₀) | `exit.speed_ratio`, `exit.T0_K` | `cai2012.inflow` |
| core cell size | `mesh.target_cell_over_mfp`·λ₀, capped by `mesh.max_core_cell_over_D`·D and `mesh.max_cells` | `cai2012.mesh` |
| particle weight | n₀, exit-cell volume, `resolution.target_particles_per_cell`, ÷ the particle multiplier | `cai2012.inflow.derive_run_settings` |
| `deltaT` | `dsmc.courant_target`, the smallest cell, U₀ + 3σ | `cai2012.inflow` |
| transient, end time, write interval | `dsmc.transient_basis` and the transit/collision-time settings, × the study multipliers | `cai2012.inflow` |

`study.yaml` may not override `exit.knudsen` or
`dsmc.numerical_particle_multiplier` (rejected, not merged), and the run-length
and write-rate multipliers are study-wide only. Every key, unit and default is
in the [configuration reference](../reference/configuration.md#cai2012).

The committed matrix:

| | Kn100 | Kn0p1 | Kn0p01 |
|---|---|---|---|
| `Kn` | 100 | 0.1 | 0.01 |
| `overrides.dsmc.transient_basis` | `transits` (2 + 1.5) | `transits` (2 + 1.5) | `transits` (2 + 1.5) |
| `overrides.dsmc.n_subdomains` | 12 | 12 | 12 |
| `overrides.mesh.max_cells` | — | — | 4 000 000 |
| particle levels | np1x, np2x, np5x, np10x | same | same |
| `run_time_multiplier` / `output_frequency_multiplier` (study-wide) | 3.0 / 4.0 | same | same |

The template's own default is `transient_basis: cai` — Cai's 10⁴ reference
collision times before sampling. The committed cases override it to two domain
transits; [Cai 2012 §5.1](../cai2012-case.md#51-the-transient) explains the
measurement behind that and what it costs in the far field.

## Cheap checks (no OpenFOAM)

From `cases/cai2012/`, in WSL or Linux (the scripts are executable Python; on
native Windows call them as `python generate_cases.py …`):

```bash
./generate_cases.py --dry-run            # list the cases that would be generated; writes nothing
```

The next two steps **write**, but only gitignored generated files (`Cases/`,
`manifest.yaml`, and each case's `system/`, `constant/` dictionaries):

```bash
./generate_cases.py                      # clone baseCase x 12, derive, write manifest.yaml
./AllmeshCases --dict-only               # each case's dictionaries; no OpenFOAM
./validate_cases.py                      # exit 0 if the tree is the study, 1 if not
```

`generate_cases.py` runs the full derivation and the DSMC quality checks for
every case, so a case whose mesh cannot be built is found here rather than an
hour into meshing. `validate_cases.py` reads the **generated dictionaries**, not
the Python that wrote them, and checks that a case's four particle levels
differ in the particle weight and nothing else. These prove the inputs are
consistent; they say nothing about the solution.

Inside one case, `./Allmesh --dict-only` prints the derived gas, exit state,
mesh plan, run settings, estimated parcel counts and the check report, then
writes the dictionaries — the quickest way to see what a `case.yaml` edit
implies. The literal translation of Cai's uniform grid (4 × 10⁹ cells) is
printed before anything is written.

## Production run

From `cases/cai2012/`:

```bash
./AllmeshCases            # blockMesh, topoSet, createPatch, checkMesh, nozzle check -- per case
./validate_cases.py       # again, before spending compute
./AllrunCases             # solve every case in manifest order
./AllpostCases            # validation outputs, study table, then imagery
```

Every study runner reads `manifest.yaml` through
`python -m plumetools.casemanifest` and checks the **whole** manifest before
touching any case. Subsets, for a partial run or a job array:

```bash
./generate_cases.py --knudsen 100        # one physical case, all four levels
./generate_cases.py --particles 1        # all three cases, 1x only ('1' or 'np1x')
./AllrunCases --list                     # numbered case list
./AllrunCases --index 0                  # one case by number (0-based)
./AllrunCases --case Kn100_np2x          # one case by name or path
./AllrunCases --keep-going               # do not stop at the first failure
```

`--list`, `--index` and `--case` work the same on `AllmeshCases`. There is no
PBS or Slurm script for this family; `--index "$SLURM_ARRAY_TASK_ID"` is the
pattern the script headers suggest.

Per case, from `Cases/<name>/`:

```bash
./Allmesh                 # dictionaries + mesh + nozzle carving + verification
./Allrun                  # or --serial, -np N, --no-solve
./Allpost                 # or --time T for a specific time directory
```

`./Allrun --no-solve` writes `0/` and runs the checks without the solver; it
needs the mesh, because the inflow faces come from it.

### Continuing a run

Re-running `./Allrun` **continues** from the newest checkpoint that is complete
on every rank (`startFrom latestTime` in the generated `controlDict`, plus
`python -m plumetools.foamio.checkpoints plan`). On a resume, `runInflow.py`
and `dsmcInitialise` are skipped, `decomposePar` is skipped or narrowed to the
resume time, and `reconstructPar -newTimes` adds only new times. `fieldAverage`
continues from the accumulators stored in each time's `uniform/`. A case that
has reached `endTime` reports so and exits 0.

To carry a finished case further, raise the end time in `case.yaml` (for
example `dsmc.sampling_domain_transits`), then:

```bash
./Allmesh --dict-only     # rewrites controlDict; does NOT re-mesh
./Allrun                  # continues from the latest time
```

`0/` is **not** regenerated on a resume, so a physics edit does not take hold;
to change physics, start over. Details and failure cases:
[Restart and recovery](../guides/restart-and-recovery.md).

!!! danger "Commands that destroy results"
    - `./Allclean` (per case) removes solver output and the generated `0/`;
      `--mesh` also removes the mesh and dictionaries. Preview with `--dry-run`.
    - `./AllcleanCases --purge` deletes the **whole** `Cases/` tree and
      `manifest.yaml`. `./AllcleanCases --dry-run` lists what would go.
    - `./generate_cases.py --overwrite` replaces cases that already contain
      results.
    - `./Allmesh --force` re-meshes a case that has results; the guard exists
      because the results would then address cells that no longer exist.

## Outputs

Per case, in `Cases/<name>/results/` (from `./Allpost`, reading the
**time-averaged** fields — a single-step `rhoN` measures shot noise):

| File | Contents |
|---|---|
| `centerline.csv` | `x_over_D`; `n_over_n0`, `U_sqrt_beta0`, `T_over_T0` from DSMC; each with `_analytical` (Cai's solution averaged over the **same cells** as the DSMC sample, which removes the tube-averaging bias) and `_analytical_axis` (exactly on the axis); `n_cells` per sample |
| `density_plane.csv` | `x_over_D`, `z_over_D` (the `post.plane: xz` lateral axis), `n_over_n0` at the cell centres of the centre plane |
| `metrics.yaml` | max / mean / RMS relative error against the analytical solution, per centreline quantity, with the case's Kn, n₀, cell/λ₀ and Cai's reported error as a reference value |
| `centerline-density.png`, `centerline-velocity.png`, `centerline-temperature.png` | the centreline figures |
| `density-contour.png` | n/n₀ = 0.1, 0.01, 0.001, DSMC over analytical |
| `viz/` | slice imagery and its `manifest.yaml`, if `pvpython` was available |

Study level: `manifest.yaml` (every derived input per case — Kn, D, λ₀, T₀, U₀,
n₀, weight, minimum cell, `deltaT`, schedule, `fieldAverage` set-up, `mesh_id`)
and `results/study-table.csv` (one row per case:
`case, Kn, n0_per_m3, cell_over_mfp, n_cells, time,
density_{max,mean,rms}_rel_error_percent, cai_reported_max_percent,
velocity_max_rel_error_percent, temperature_max_rel_error_percent`). Full
schemas: [Outputs](../reference/outputs.md#cai2012).

**Judging the output.** Look first at the Kn = 100 density, where the
collisionless solution should hold: agreement near the exit, and a far field
that may still be transient-limited at the committed 2-transit start (see
[§5.1](../cai2012-case.md#51-the-transient)). At Kn = 0.1 and 0.01 the
departure should have the physical sign: denser than collisionless near the
exit and thinner downstream, faster on the axis, cooler. Cai's reported maximum
errors (0.07 %, 3.63 %, 12.03 %) are carried as **reference values, not
tolerances**. Kn = 0.01 does not meet Cai's Δx/λ₀ = 1 within the cell budget and
the checks say so on every report; that biases its collision rate low.

## Resources

Configured: 12 subdomains per case (Open MPI counts physical cores, not
threads); `mesh.max_cells` 4 × 10⁶. Planned mesh sizes, parcel counts and step
counts are printed by `./Allmesh --dict-only` and recorded in the manifest;
[Cai 2012 §4.3](../cai2012-case.md#43-resolution-actually-achieved) tabulates
them for the committed settings. No measured wall-clock time is committed for
this family; the case README's earlier rough figures (an hour for Kn = 100 on 12
cores, several hours for Kn = 0.01) are estimates, not measurements.

## Variants and safe customisation

| Want | Do | Notes |
|---|---|---|
| Skip a case | `enabled: false` in `study.yaml` | keep the entry; it records the intended matrix |
| Cai's own transient | remove the `transient_basis: transits` overrides | 10⁴ t₀ ≈ 0.05 s ≈ 36 000 steps per case |
| Longer averaging | `run_time_multiplier` (study-wide) | moves `endTime`, not the averaging start |
| More frames | `output_frequency_multiplier` (study-wide) | write interval stays a whole number of steps |
| Half the domain | `geometry.symmetry_mode: half_y` in `baseCase/case.yaml` | opt-in, never automatic; changes the comparison |
| Another Kn | a new `kn_cases` entry | the derivation follows; check `./Allmesh --dict-only` for the cell budget |

After editing `baseCase/case.yaml` or `study.yaml`, regenerate. A generated
case keeps the scripts it was cloned with; `generate_cases.py` refuses to
overwrite a case with results unless `--overwrite` is given.

## How it differs from markelov1999

The family follows `markelov1999`'s design — `study.yaml` → generated cases →
`case.yaml` per case → generated dictionaries → manifest — with two deliberate
departures. **No CaseFoam**: the Markelov study is a hierarchy (gap over
pressure), which CaseFoam builds; this is a flat list, so `generate_cases.py`
uses `shutil.copytree` and has no extra dependency. **Its own config loader**:
`plumetools.config` cross-validates a source-flow sphere and throat radius this
case does not have, and the regression golden is bound to it; the two loaders
reject each other's files by `model:` (this one is
`model: cai2012_circular_plume`).
