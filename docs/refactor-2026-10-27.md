## The defects

Each was reproduced on the pre-refactor code before it was changed; the commit
message records trigger, previous behaviour, correction and tests.

1. **Incomplete checkpoint accepted.** `Allrun` resumed from processor0's
   newest time; `hpc finished` took the newest time on any rank; a
   decomposition change ran `decomposePar -force` over newer processor state.
   Now a time counts only when complete on every rank (time state present,
   every file ending with OpenFOAM's end divider, the same files on every
   rank, no vanished parcel cloud); a newer partial time stops the run naming
   what is missing; a decomposition change reconstructs newer processor state
   first. Nothing deletes or moves a time directory.
2. **Malformed fields broadcast.** A list declaring four values and holding one
   was read as uniform and copied across the mesh. Now lists must hold their
   declared count and their mesh's cell or face count; only `uniform` entries
   expand; binary files and non-numbers are refused.
3. **Partial manifest accepted.** `mapfile < <(python ...) || die` never saw the
   Python's failure, and paths were printed as read. Now the whole manifest is
   checked before any path is printed, and the listing is captured first.
4. **Weak evidence compatibility.** A `pass` with a matching threshold was
   enough. Now the evidence must record, and match, the model, purpose, Bird
   definition and threshold, core angle, tails, closure exponent and source
   problem; Knudsen number, R, mesh and weight may differ.
5. **Test/configuration disagreement.** Two tests expected the production
   interfaces to be configuration-incomplete; since `ad4cdc6` they are
   complete, meshable, numerically unsuitable and refused at the run step.
   The tests now check the three separate decisions (mesh, run, label); no code
   changed.

## Evidence

**Generated files.** Every generator that runs without casefoam was run before
and after, from the same case files at the same path, and the trees compared
byte for byte (a scratch comparison script): `cai2012` (12 cases' dictionaries,
one meshed case and its `0/`), `cai2012-kn-extension` (7 direct cases, 6
interface cases, reports, manifests, one meshed interface case and its `0/`),
the three `r-4d` cases (dictionaries, `describe`, `0/` on the local mesh),
`markelov1999/baseCase` dictionaries -- 771 files, 47 steps. At `4b3b399`:
716 files byte-identical; 3 differ only in `generated_utc`; 7 OpenFOAM logs
only in their header and timings (time, PID, "in = x s"); 45 are the scripts
changed on purpose -- every `Allrun` and the copies generation puts in each
case (defect 1), the twelve family runners (defect 3), `smoke_cases.py`. Every
dictionary, `0/` field, manifest and report is identical, the 47 steps exit
with the same statuses, and their output differs only in traceback file paths.
Each class is listed line by line, never filtered. One earlier run also showed
a snappyHexMesh log with the same lines interleaved differently -- stdout and
stderr of one OpenFOAM run, on identical dictionaries, with identical
`checkMesh` statistics and identical `0/` downstream. `cai2012-health` and
`markelov1999` case generation need casefoam, which is not installed here, so
those families are covered by their unit tests, not by regeneration; the
3d-inflow regression golden needs a gitignored mesh that is not in this
checkout and skipped before and after.

**Tests**, in WSL (Python 3.12.3, numpy 2.5.4, OpenFOAM v2512 with the
plumeFieldInflow library):

| tier | before (`a5eb48b`) | after |
|---|---|---|
| `tests/unit` | 2054 passed, **2 failed** (defect 5), 6 skipped | 2177 passed, 0 failed, 6 skipped |
| `tests/regression` | 20 skipped | 20 skipped |
| `tests/openfoam -m needs_openfoam` | 66 passed | 66 passed |

The 6 skips need casefoam; the regression golden needs the gitignored
3d-inflow mesh, which is not in this checkout (its restore tag is not on the
remote either). The OpenFOAM tier runs real blockMesh, snappyHexMesh,
dsmcFoam -- serial and resumed -- through the converted `Allrun`s. No HPC job
was submitted: `runCase.sh`, `hpc guard/label/finished/record` and the
`Allrun` decomposition paths were exercised locally, with stub tools where a
cluster is needed, not on a scheduler.

**Performance**, R-4D baseCase mesh (44 MB `faces`, 537 065 points), best of
two, peak RSS of a fresh interpreter, identical output digests:

| operation | before | after |
|---|---|---|
| `inflow.read_patch_geometry` (nozzle) | 13.60 s, 592 MiB | 4.80 s, 250 MiB |
| `mesh.patches.read_patches` (all 7) | 5.96 s, 277 MiB | 1.45 s, 96 MiB |
| `mesh.polymesh.read_face_range` (nozzle) | 0.45 s, 237 MiB | 0.42 s, 42 MiB |

would not have fitted alongside everything else in the 15 GB WSL VM.
