# Traceability and a learning path: design

Approved in a design discussion with the owner on 2026-11-04, against `main` at
`3612457`. This page is the specification; the implementation plan is written
from it. Nothing here adds or removes a capability: every case, script option,
generated dictionary and result stays as it is.

## 1. Purpose

A junior engineer who already knows Python, CFD and DSMC should be able to pick
up this repository, learn how its cases work, and set up a case of their own,
quickly. Two kinds of traceability serve that:

- **Reading trace** (the priority): from a physical input in `case.yaml`, through
  the equation and the function that apply it, to the entry it becomes in a
  generated OpenFOAM dictionary, and on to the solver and the outputs, without
  having to reverse-engineer the code.
- **Run trace**: a short, per-case record of what each script actually executed,
  what it derived and which decisions it took.

## 2. Decisions taken

| Question | Decision |
|---|---|
| Which traceability | Reading trace first; run trace as well; code restructuring (module splits, `Allrun` de-duplication) **deferred** to a later effort |
| Run trace constraints | Uncluttered; must not change output behaviour; verified end to end on representative cases, not on every case |
| Reader | Knows Python, CFD and DSMC. DSMC itself is not taught; this repository's conventions are, and its own terms (*interface track*, *overlap evidence*, *NON-PRODUCTION*, ...) are defined where they first appear |
| "Set up their own case" | Tutorials target a **new configuration in an existing family** (edit `case.yaml`, check, run, judge). A modest code extension (a diagnostic, a derived output) gets a signposted guide. A new family stays on the existing checklist |
| Compute budget | Every teaching run serial on a laptop: 1 core, < 2 GB, at most 3 minutes wall-clock. One optional lesson uses 2 ranks |
| Keeping the reading trace true | Trace maps held as **checked data** in a new reporting package (§6.1); not hand-written tables, not instrumentation of the derivation code |
| Trace pages | Generated from the maps, **committed**, and guarded by a drift check |
| Existing tutorials | Moved, unchanged in content, to `docs/families/` and renamed *Family guides*; a new *Learn* section holds the real tutorials |
| Archived and legacy cases | Covered read-only (Phase 3). A runnable 1-D expansion is **not** in scope; it is a proposed follow-on spike (§9) |

## 3. Starting point

What already exists, and is kept: the MkDocs site (getting started, 13 per-family
tutorials, guides, CLI/configuration/output references, explanations, the
architecture page, known gaps); `[PAPER]`/`[ASSUMPTION]`/`[DERIVED]` tags on every
`case.yaml` value; a `GENERATED by ... from case.yaml` header on every generated
dictionary; cheap checks in every family (`--dry-run`, `--dict-only`,
`describe`); `describe()` methods that already print derivations with formulas
and values (`U0 = S0 sqrt(2 R T0)  707.0 m/s`).

What a junior engineer cannot get from it today:

1. **The trace stops at the generated file.** `constant/dsmcProperties` says it
   came from `case.yaml`; it does not say which function turned which keys into
   its `nEquivalentParticles`.
2. **What a run executed is scattered.** `Allrun` is 344 lines of bash; its
   decisions (resume, decompose, reconstruct first) and its steps are spread over
   the console and one `log.<tool>` per step. The derivation printed by
   `Allmesh` is not saved.
3. **No tutorial is built for learning.** The current tutorials are operational
   guides to production families, dense with evidence status and blockers. No
   case exists to be cheap and instructive.
4. **"Set up your own" has only the heavy path.** [Extending the
   workflows](../../development/extending-workflows.md) covers a whole new
   family; nothing walks through a new case inside an existing one.

## 4. Scope

**In scope:** the `plumetools/trace/` reporting package and its checks; generated
trace pages; the run trace (`log.trace`); the documentation layout change; the
Learn section and its teaching cases under `cases/learn/`; one how-to guide for a
modest code extension; read-only trace pages for the archived and legacy cases.

**Out of scope:** splitting modules or de-duplicating scripts; fixing anything on
the [known-gaps](../../development/known-gaps.md) list; any change to physics,
defaults or configuration schemas; any edit to the frozen packages (`cai2012`,
`markelov1999`), to an archived case directory, or to the unrunnable legacy
cases' files.

### Phases

| Phase | Families and cases | Delivers |

| **2** | `cai2012ext` (direct cases and interface track), `cai2012-health` (sweep generation), `cai2012-virtual-collision`, `markelov1999`, `hybridplume`, `3d-inflow` | Maps and trace pages for each; run-trace hooks in each family's own scripts (including `Allviz` where present); verified by the output diff and unit tests, not by a solver run per family |
| **3** | Archived: `1d` first, then `2d-wedge`, `2d-planar`, `caseFoamEx`, `wake-cylinder`. Legacy: `iss_solar_panels{,_2,_3}`, `solar_panel_particle_resolution_study` | One static trace page per case, built from `StaticEntry` maps (§6.8). Documentation only; no file in those case directories changes; no run trace |

## 5. Invariants

Each is checked, not assumed (§7).

1. **Generated outputs are byte-identical.** Every generated dictionary and `0/`
   field of every runnable family's `baseCase` (and of every case a study
   generator writes) is the same before and after each phase.
2. **Scripts behave the same.** Every existing script keeps its options, its exit
   statuses and its console output (stdout and stderr). The run trace is written
   silently to its own file.
3. **Tracing never fails a run.** If the trace cannot be written or the
   derivation cannot be recorded, the step proceeds exactly as before.
4. **The existing checks stay green.** The unit suite passes unchanged; the strict
   docs build, `check_api.py`, `check_links.py` and `run_examples.py` pass.

## 6. Design

### 6.1 The `plumetools/trace/` package

A reporting package. It imports the families' **public** names; no family package
imports it. The runner scripts call it (§6.4), always inside a guard.

```
plumetools/trace/
  __init__.py      record_derivation(), the public entry for scripts
  __main__.py      python -m plumetools.trace pages [--check]
  model.py         TraceEntry, StaticEntry, FamilyMap
  pages.py         renders a FamilyMap to Markdown
  checks.py        the checks of §6.2, callable from tests and from the CLI
  maps/
    cai2012.py     Phase 1
    nozzleplume.py Phase 1
    ...            one module per family (Phase 2) and per archived/legacy case (Phase 3)
```

**`TraceEntry`** (runnable families), one per traced value:

| Field | Example |
|---|---|
| `target` | `constant/dsmcProperties : nEquivalentParticles` |
| `quantity` | `particle weight (-)` |
| `formula` | `W = n0 · V_exit / N_exit` (plain text; used verbatim on the page and in `log.trace`) |
| `producer` | `plumetools.cai2012.inflow.derive_run_settings` |
| `value` | `run.n_equivalent_particles` (an attribute path on the derived objects) |
| `inputs` | `exit.knudsen`, `nozzle.diameter_m`, `resolution.target_particles_per_cell`, ... |
| `tag` | one of the repository's existing tags (`PAPER`, `ASSUMPTION`, `DERIVED`, `NUMERICAL`, ...) or the new `TEACHING` (§6.7) |
| `explained_in` | optional link to the explanation page that justifies it |

**`StaticEntry`** (Phase 3): the file and line where a value is set or used, the
text expected on that line, the script that consumes it, and the `AR-` findings
that apply.

**`FamilyMap`**: the family's name, its lifecycle-stage table (which module owns
load, derive, assess, write dictionaries, mesh, initialise, solve, post), its
entries, its boilerplate allowlist, and an `objects(case_dir)` function that
calls the family's public derivation **in the same order as that family's
`Allmesh`** and returns the named objects (`cfg`, `geom`, `exit_state`, `plan`,
`run`, ...). `objects` is used by the checks and the page generator only; during a
real run, `Allmesh` passes the objects it has already derived.

**Granularity.** Every scalar entry in `dsmcProperties`, `controlDict`,
`dsmcInitialiseDict`, `decomposeParDict` and every `0/` boundary value gets its own
entry. Mesh dictionaries (`blockMeshDict`, `snappyHexMeshDict`, `topoSetDict`,
`createPatchDict`) get one entry per dictionary, naming the plan object and the
renderer, not one per vertex.

### 6.2 Checks

Unit tests in `tests/unit/test_trace_*.py`, no OpenFOAM:

1. Every `producer` resolves (import, then attribute lookup).
2. Every input key is one the family's loader accepts (the loaders already
   reject unknown keys, so the accepted set is known).
3. **Value check.** For each `baseCase` and teaching case, the family's own
   dictionary writer is run into a temporary directory; every `target` entry is
   read back and compared with the map's `value`, to within half a unit in the
   last digit the writer prints.
4. **Completeness.** In each traced dictionary, a scalar entry that is neither
   mapped nor on the family's boilerplate allowlist fails the test. An allowlist
   entry must be a literal constant in the renderer, never a derived value.
5. Every `StaticEntry` file exists and its line contains the expected text.

**Drift check.** `python -m plumetools.trace pages --check` regenerates every
trace page in memory and compares it, character for character, with the
committed file; a difference fails with the command that regenerates it. It runs
in the unit suite (`test_trace_pages.py`) and in the `docs.yml` job that already
installs `plumetools` (the one running `run_examples.py`). It cannot run inside
`mkdocs build`, which deliberately has no scientific runtime.

### 6.3 Trace pages

Generated into `docs/trace/<family>.md` (Phase 3: `docs/trace/archive/<case>.md`),
committed, LF line endings. Each page has: a header naming its map module and the
regenerate command; the family's lifecycle-stage table; then one table per
generated file with the columns *entry · quantity · formula · computed by ·
from `case.yaml` · tag · `baseCase` value*. Including the `baseCase` value means
a deliberate physics change appears in the page diff of the same commit.

`docs/trace/index.md` is hand-written: how to read a trace page, how to read a
`log.trace`, and the list of pages.

### 6.4 The run trace

**File.** `log.trace` in the case directory. The name falls under every existing
`log.*` rule: gitignored; pruned when `cai2012.study` clones a template; removed by
the Markelov and 3d-inflow `Allclean`, which glob `log.*`. The Cai and r-4d
`Allclean`, which name their logs, gain `log.trace` in that list.

**Append-only.** Each invocation of `Allmesh`, `Allrun` or `Allpost` appends one
block; a resumed run reads as a second `Allrun` block.

**Line grammar.** Fixed columns, one line per event; solver output is never
copied, only pointed to.

```
== <script>  <ISO-8601 time>  [<options>]  host=<hostname>  plumetools=<short sha>|unknown  OpenFOAM=<version>|none
   derive   <entry>  <value> [<unit>]  <formula>  <producer>
   decide   <text>
   step     <tool>  ok|FAILED(<status>)  <elapsed> s  <log file>
   note     <text>
== end <script>  exit=<status>  <elapsed> s
```

```
== Allmesh  2026-11-04T10:12:03  host=laptop  plumetools=3612457  OpenFOAM=v2512
   derive   deltaT                  2.57e-06 s   dt = C·dx_min/c_max      cai2012.inflow.derive_run_settings
   derive   nEquivalentParticles    1.48e+10     W = n0·V_exit/N_exit     cai2012.inflow.derive_run_settings
   step     blockMesh       ok   1.2 s   log.blockMesh
   step     topoSet         ok   0.3 s   log.topoSet
== end Allmesh  exit=0  2.1 s
== Allrun   2026-11-04T10:13:10  --serial  host=laptop  plumetools=3612457  OpenFOAM=v2512
   decide   checkpoints plan: RESUME=no DECOMPOSE=none np=1
   step     dsmcInitialise  ok   2.1 s   log.dsmcInitialise
   step     dsmcFoam        ok  95.0 s   log.dsmcFoam
== end Allrun  exit=0  97.4 s
```

(Values illustrative.) The `derive` lines are one per map entry, about 15-25 per
family. The commit is read with `git rev-parse --short HEAD`; no dirty check,
which is slow on large or network-mounted trees. Elapsed times use
`date +%s.%N` where available, whole seconds otherwise.

**Hooks.**

- *Steps and decisions*: a small bash `trace()` function appends one line and
  ignores every error (`... >> log.trace 2>/dev/null || true`). It is called at
  the start and end of each script's existing `run()` wrapper, which every
  OpenFOAM step already passes through, and at the decision points the scripts
  already have (checkpoint plan, already at `endTime`, refused re-mesh).
- *Derivation*: one call, `plumetools.trace.record_derivation(".", "<family>",
  cfg=..., exit_state=..., run=..., ...)`, inside the Python block `Allmesh`
  already runs, after the objects exist. The import and the call sit in a
  `try`/`except Exception` that never raises; on failure, `log.trace` gets
  `note derivation not recorded: <reason>` and the console gets nothing.
- *End line*: from an `EXIT` trap; where a script already sets one, the call is
  added inside it.

**Coverage.** Phase 1: the Cai per-case scripts (`Allmesh`, `Allrun`, `Allpost`,
`Allclean`), kept byte-identical across `cai2012`, `cai2012-health` and
`cai2012-kn-extension`; r-4d's three variants; the teaching cases, which copy
these scripts. Study runners (`AllrunCases`, PBS `run*.sh`) are not traced
themselves; the per-case scripts they call are. Cases generated before the change
keep their old scripts until `generate_cases.py --refresh`, as today; the family
guides say so.

### 6.5 Documentation layout

```
Home
Getting started        installation · first run (ends by pointing to Learn) · repository map
Learn          (new)   index: the path, prerequisites, time and compute per lesson; lessons 0-4
Family guides  (moved) docs/tutorials/*.md -> docs/families/*.md, content unchanged,
                       plus a "Trace" row in each at-a-glance box: a link to the family's
                       trace page, or "not yet traced (Phase 2)" until it has one
Trace          (new)   index (hand-written) · one generated page per family · archive/ (Phase 3)
Guides                 + "Add a diagnostic or a derived output"
Reference · Explanation · Development · Archive   unchanged except as listed below
```

**Moving the family guides.** `git mv` keeps their history. Every link to them is
updated: `mkdocs.yml` nav, the root README, case READMEs and cross-links;
`check_links.py` fails on any that is missed. If an archived file links to a moved
page, a one-line stub stays at the old path rather than the archived file being
edited.

**Other documentation edits:** the root README's quick start gains a "new here:
start with Learn" line; [Extending the
workflows](../../development/extending-workflows.md) gains rows for updating a
trace map and regenerating pages; the repository map lists `plumetools/trace/`,
`cases/learn/`, `docs/trace/` and the `[TEACHING]` tag; the CLI reference
documents `python -m plumetools.trace`; the outputs reference documents
`log.trace`; the configuration reference documents `[TEACHING]`; the case catalog
lists the teaching cases; the Archive index links to the Phase 3 pages; the
known-gaps page records the 1-D spike proposal (§9).

### 6.6 The Learn section

| # | Lesson | Case | Teaches | Time |
|---|---|---|---|---|
| 0 | **How a case runs** (reading; lives under Explanation, first stop of the path) | none | The lifecycle every family shares: `case.yaml` -> load and validate -> derive -> assess -> write dictionaries -> mesh -> initialise -> solve -> post-process; a table of each family's module per stage; where physics enters and where it is checked | ~15 min |
| 1 | **A collisionless plume against Cai's analytical solution** | `01-cai-collisionless` | Reading a `case.yaml` and its tags; `Allmesh --dict-only` and its derivation and checks; deliberately coarsening the nozzle to D/10 and watching the family refuse it (area error -6.9 % against the 5 % limit); meshing, a serial run, `Allpost`; judging DSMC against the analytical centreline, and what agreement to expect at this size | ~30 min, solver ≤ 3 min |
| 2 | **Trace one number** | lesson 1's case | Following `nEquivalentParticles` from `case.yaml` through the trace page, the producing function, the `derive` line in `log.trace`, `constant/dsmcProperties` and `log.dsmcFoam`; then predicting the effect of changing the occupancy target before regenerating | ~20 min, no solver |
| 3 | **Build your own nozzle-on-a-plate case** | `03-own-plate` | Choosing an exit state, gas and plate in `nozzleplume`; iterating with `describe` until every check passes within the cost guard; `snappyHexMesh`; a serial run; reading the plate outputs | ~45 min, solver ≤ 3 min |
| 4 | **Optional: two ranks, interrupt and resume** | lesson 1's case | Running half the end time (`run_time_multiplier: 0.5`), then `Allmesh --dict-only` and `Allrun --np 2` to resume — the repository's documented path — and reading the checkpoint plan in `log.trace` | ~20 min, solver ≤ 3 min |

**Guide: add a diagnostic or a derived output.** A step-by-step how-to following
[Rarefaction diagnostics § Adding a
diagnostic](../../rarefaction-diagnostics.md#adding-a-diagnostic) and the "a
derived quantity" row of [Extending the
workflows](../../development/extending-workflows.md), ending with updating the
family's trace map and regenerating its page.

Lessons run in a copy, `cases/learn/runs/<name>/` (gitignored), so the committed
case stays clean and a re-run starts fresh. Every Python-only step of every lesson
is added to the `run_examples.py` allowlist, so CI executes it.

### 6.7 Teaching cases

```
cases/learn/
  README.md                 links to the Learn section
  01-cai-collisionless/     case.yaml + the cai2012 baseCase scripts, byte-identical
  03-own-plate/             case.yaml + the r-4d baseCase scripts, byte-identical
  runs/                     gitignored working copies
```

Both are built **from `case.yaml` values alone**. Their sizes, from each family's
own estimator at `3612457`:

| Case | Configuration | Cells | Steps | Parcels (steady, estimated) | Family checks |
|---|---|---|---|---|---|
| `01-cai-collisionless` | Cai Kn = 100; `symmetry_mode: half_y`; domain 3 D × 1.5 D × 1.5 D; core cell D/12.5 over 1 D × 0.75 D; 8 outer x cells, 4 lateral; `transient_basis: transits`, 2 transient + 2 sampling transits; 10 particles per exit cell; post range 3 D | 7,938 | 1,652 | 2.3 × 10⁴ | all OK (nozzle area +1.0 %) |
| `03-own-plate` | `execution_profile: smoke`; invented argon thruster D = 5 cm, 300 K, 700 m/s, n = 6 × 10¹⁹ m⁻³ (Kn ≈ 0.44); 30 cm × 30 cm × 2 cm plate at 25 cm; `x_max_m` 0.32, `y_half_m` = `z_half_m` = 0.2, symmetry planes y and z (a quarter is meshed); 1 cm background cells, one level-1 exit region; 10 parcels per exit cell; 3 transient + 2 sampling transits | 12,909 | 3,320 | 2.1 × 10⁴ | all OK (nozzle area +1.9 %) |

**The `[TEACHING]` tag** marks every value chosen for cost, with a comment giving
the production value and why it changed. It is documented with the other tags.

**Rules held by tests:**

- *Scripts identical*: each teaching case's scripts equal its family's `baseCase`
  scripts byte for byte, and the three Cai `baseCase` copies equal each other
  (today a documented property with no test).
- *Cost guard*: each teaching case's estimate stays at or below 20,000 cells,
  5,000 steps and 5 × 10⁴ parcels, and passes every family check.
- *Measured runtime*: a `needs_openfoam` test runs lesson 1 end to end. It is run
  on the owner's laptop (WSL, OpenFOAM v2512), and the measured solver time is
  recorded in the lesson. A run over 3 minutes is tuned down by `case.yaml` values
  only.

`.gitignore` gains narrow entries for the teaching cases' generated dictionaries,
fields and `runs/`, following the per-family convention.

### 6.8 Phase 3: archived and legacy cases

One page per case under `docs/trace/archive/`, generated from a `StaticEntry` map
in `plumetools/trace/maps/`. Each page records: what the case was for and its
reference (for `1d`, the Stewart & Lumpkin (2012) DAC isentropic expansion, the
repository's validated lineage); its physical inputs with file and line; which
script sets, reads or plots each; the order the scripts were meant to run in;
the `dsmcFoam+`/v1706 features it depends on (`boundariesDict`,
`controllersDict`, Larsen-Borgnakke VHS); the `AR-` findings from
[`cases/ARCHIVE.md`](../../../cases/ARCHIVE.md) that apply; and why it does not run
on the supported stack. No file in the case directories changes.

## 7. Verification

1. **Output diff.** Before the first change, every runnable family's `baseCase`
   (and each study generator's cases) is generated with `--dict-only`, `describe`,
   `setup` or `--dry-run` as the family provides, from `3612457`, into a scratch
   directory outside the repository; files and console output are kept. After
   each phase the same is regenerated and compared byte for byte. The existing
   pinned tests run as well.
2. **Trace checks.** §6.2's five checks and the drift check, in the unit suite.
3. **Run trace.** A format test of the line grammar; a test that a script still
   exits 0 with identical console output when `log.trace` cannot be written (it
   is a directory) and when `plumetools.trace` cannot be imported; a test that
   `Allclean` removes `log.trace`.
4. **Teaching cases.** The identical-scripts and cost-guard tests (§6.7).
5. **Docs.** Strict build, `check_api.py`, `check_links.py`, `run_examples.py`
   with the lessons' steps, all green.
6. **One solver run.** Lesson 1's `needs_openfoam` test on the owner's laptop,
   with its measured time recorded; lessons 3 and 4 are run there once as well.
7. **Independent review.** Each phase is reviewed by a reviewer that did not
   write it, against this specification.

## 8. Risks

| Risk | Handling |
|---|---|
| A trace hook changes console output or an exit status | Invariant 2 and the run-trace tests; all trace output goes only to `log.trace` |
| The three identical Cai script copies diverge | Changed in lockstep; the new identical-scripts test |
| Boilerplate allowlists grow to hide derived values | Allowlist entries must be literal constants in the renderer; reviewed per phase |
| Teaching-case estimates are rough (parcel counts are labelled `[ROUGH]` by `nozzleplume`) | The measured run on the owner's laptop decides; re-tune by `case.yaml` only |
| Phase 2 families (`cai2012ext`, `hybridplume`) have many derived values | Same granularity rule; scalar entries traced, mesh dictionaries per dictionary |
| Lesson 4's half-length first leg: `run_time_multiplier` does not move `average_start_s`, and the write schedule is derived from the end time, so the first leg may end before sampling starts or write at different times from the full run | Checked with `--dict-only` before the lesson is written; if the documented path does not suit, the lesson stops the solver after a write and resumes from that checkpoint instead |
| Line endings: the repository has no `* text=auto` rule | New files are written with LF endings |
| Generated cases keep their old scripts | Documented; `--refresh` already exists |

## 9. Deferred and follow-on work

- **Code structure** (module splits, de-duplicating the runner scripts): a later
  effort, with its own specification.
- **Spike: a runnable 1-D expansion on the supported stack.** Question: can
  standard `dsmcFoam` v2512, with this repository's boundary models, run the
  radial-sector isentropic expansion of the archived `1d` case (Stewart & Lumpkin
  2012) without `dsmcFoam+` features? Output: a recommendation. If yes, a
  separate specification for an active 1-D teaching case, which would be a new
  capability and so outside this effort.
- The known gaps stay as recorded.

## 10. Acceptance

**Phase 1** is done when: `plumetools/trace/` exists with `cai2012` and
`nozzleplume` maps passing every check; `docs/trace/` holds their committed pages
and passes the drift check; the Phase 1 scripts write `log.trace` as specified
and pass the run-trace tests; the family guides live in `docs/families/` with no
broken link; the Learn section, lessons 0-4 and the extension guide are written;
both teaching cases pass the cost guard and lesson 1 has a measured run time of at
most 3 minutes; invariants 1-4 hold.

**Phase 2** is done when every Phase 2 family has a map, a page and run-trace
hooks passing the same checks, and invariants 1-4 hold.

**Phase 3** is done when every listed archived and legacy case has a static trace
page whose `StaticEntry` checks pass, with no file changed in those case
directories.
